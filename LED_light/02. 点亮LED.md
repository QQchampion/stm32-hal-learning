## 1. 实验目标

- 学会根据原理图确定 LED 对应的 GPIO 引脚；
- 使用 STM32CubeMX 将 GPIO 配置为输出模式；
- 使用 HAL 库控制 LED 点亮、熄灭和闪烁；
- 掌握 LED 不亮时的基本排查方法。

---

## 2. 硬件信息

> 根据自己开发板的原理图填写，不能直接照抄其他开发板的引脚。

| 项目       | 实际信息                          |
| -------- | ----------------------------- |
| STM32 型号 | `STM32F103VET6`               |
| LED 编号   | LED_G、LED_B、LED_R             |
| GPIO 端口  | `GPIOB`                       |
| GPIO 引脚  | LED_G_Pin、LED_B_Pin、LED_R_Pin |
| 点亮电平     | 低电平                           |
| 供电方式     | USB 供电                        |
### 端口和引脚的区别

STM32 的 GPIO 通常按照组进行划分：
- `GPIOA`：A端口
- `GPIOB`：B端口
- `GPIOC`：C端口

以 `PB5` 为例：
- `B`：表示它属于 `GPIOB` 端口；
- `5`：表示它是该端口的第5号引脚；
- `PB5`：就是完整的引脚名称。

类似于：
> `GPIOB` 是一栋楼，`PB5` 是这栋楼里的5号房间。

### LED 有效电平

需要先查看原理图，确定 LED 的连接方式。

电路为：
```text
3.3V → LED → STM32 GPIO
```
则 GPIO 输出低电平时形成电流回路，LED 点亮；输出高电平时，LED 熄灭。这种情况称为**低电平点亮**。

---

## 3. 实验原理

GPIO 是通用输入输出接口。控制 LED 时，需要完成以下过程：
```text
开启 GPIO 时钟 → 配置 GPIO 为输出模式 → 输出高/低电平 → 控制 LED 亮灭
```
GPIO 外设必须有时钟才能工作，因此初始化 GPIO 前需要先开启对应端口的时钟。

## 4. STM32CubeMX 配置

### 4.1 配置引脚

1. 找到 LED 对应的 GPIO 引脚；
2. 将该引脚设置为 `GPIO_Output`；
3. 可将 `User Label` 设置为 `LED`。

### 4.2 GPIO 参数

| 参数 | 推荐配置 | 含义 |
| --- | --- | --- |
| GPIO output level | 根据有效电平选择 | 设置上电后的初始状态 |
| GPIO mode | Output Push Pull | 推挽输出，可主动输出高、低电平 |
| GPIO Pull-up/Pull-down | No pull-up and no pull-down | 不使用内部上拉、下拉 |
| Maximum output speed | Low | LED 不需要高速翻转 |

生成工程后，应确认 `main()` 中调用了：

```c
MX_GPIO_Init();
```

## 5. 关键代码

> 下面以 `PC13`、低电平点亮为例。实际使用时，应替换成自己开发板的端口和引脚。

### 5.1 点亮 LED

```c
HAL_GPIO_WritePin(GPIOC, GPIO_PIN_13, GPIO_PIN_RESET);
```

### 5.2 熄灭 LED

```c
HAL_GPIO_WritePin(GPIOC, GPIO_PIN_13, GPIO_PIN_SET);
```

### 5.3 LED 闪烁

```c
while (1)
{
    HAL_GPIO_TogglePin(GPIOC, GPIO_PIN_13);
    HAL_Delay(500);
}
```

其中：

- `HAL_GPIO_WritePin()`：让引脚输出指定电平；
- `GPIO_PIN_SET`：输出高电平；
- `GPIO_PIN_RESET`：输出低电平；
- `HAL_GPIO_TogglePin()`：翻转当前输出电平；
- `HAL_Delay(500)`：延时 500 ms。

LED 每 500 ms 改变一次状态，因此一个“亮—灭”完整周期约为 1 s。

### 5.4 LED.c

```c
void MX_GPIO_Init(void)
{

  GPIO_InitTypeDef GPIO_InitStruct = {0}; // 定义初始化一个GPIO引脚的结构体

  /* 开启 GPIO 时钟 */
  __HAL_RCC_GPIOB_CLK_ENABLE();
  __HAL_RCC_GPIOA_CLK_ENABLE();

  /*Configure GPIO pin Output Level */
  HAL_GPIO_WritePin(GPIOB, GPIO_PIN_0, GPIO_PIN_RESET);

  /*Configure GPIO pin : PB0 */
  GPIO_InitStruct.Pin = GPIO_PIN_0; // 需配置引脚
  GPIO_InitStruct.Mode = GPIO_MODE_OUTPUT_PP; // 工作模式（输入/输出/复用/模拟）
  GPIO_InitStruct.Pull = GPIO_NOPULL; // 上拉/下拉电阻
  GPIO_InitStruct.Speed = GPIO_SPEED_FREQ_LOW; // 输出速度
  HAL_GPIO_Init(GPIOB, &GPIO_InitStruct); // 复用功能选择

}
```
#### 1. 定义初始化结构体

```c
GPIO_InitTypeDef GPIO_InitStruct = {0};
```
- `GPIO_InitTypeDef` 是 HAL 库定义的一个结构体类型，里面装着配置一个 GPIO 引脚所需的各项参数。
- `GPIO_InitStruct` 是它的一个实例，后面要往里面填参数。
- `= {0}` 表示把结构体所有成员初始化为 0，防止里面有随机垃圾值导致配置出错。这是个好习惯。

结构体里主要包含这几个成员：

|成员|含义|
|---|---|
|`Pin`|要配置哪个引脚|
|`Mode`|工作模式（输入/输出/复用/模拟）|
|`Pull`|上拉/下拉电阻|
|`Speed`|输出速度|
|`Alternate`|复用功能选择（本段没用到）|

---

#### 2. 开启 GPIO 时钟

```c
__HAL_RCC_GPIOB_CLK_ENABLE();
__HAL_RCC_GPIOA_CLK_ENABLE();
```
- STM32 的外设默认是**关闭时钟**的，不开启时钟，写寄存器的配置不会生效。
- 这两行分别给 **GPIOB** 和 **GPIOA** 供电（使能时钟）。
- 为什么开了 A 却只用了 B？因为这是 CubeMX 生成的代码，可能别处还要用 PA 口，或者你之前配置过 PA 但后来删了功能，CubeMX 没自动清理。**只用 PB0 的话，其实 `GPIOA` 那行可以删掉。**

#### 3. 填写结构体参数
```c
GPIO_InitStruct.Pin   = GPIO_PIN_0;
GPIO_InitStruct.Mode  = GPIO_MODE_OUTPUT_PP;
GPIO_InitStruct.Pull  = GPIO_NOPULL;
GPIO_InitStruct.Speed = GPIO_SPEED_FREQ_LOW;
```
- **`Pin = GPIO_PIN_0`**：选中第 0 号引脚，即 PB0。
- **`Mode = GPIO_MODE_OUTPUT_PP`**：推挽输出模式（Push-Pull）。
    - 推挽：能主动输出高电平，也能主动输出低电平，驱动能力强。
    - 对比开漏（Open-Drain）：只能主动拉低，高电平要靠外部上拉电阻。
- **`Pull = GPIO_NOPULL`**：不使用内部上拉/下拉电阻。输出模式下通常设 NOPULL 即可。
- **`Speed = GPIO_SPEED_FREQ_LOW`**：输出翻转速度设为低频。
    - 速度越高，引脚边沿越陡、功耗和电磁干扰越大。
    - 控制 LED、继电器这种慢速设备，用 LOW 就够了。如果是 SPI、PWM 高速信号才需要调高。

## 7. 本次遇到的问题

### 问题现象

使用 ST-Link 的 3.3V 给开发板供电时，Keil 显示程序烧录成功，但是 LED 没有反应；改用 USB 供电后，LED 可以正常工作。

### 原因分析

“烧录成功”只表示程序已经写入 STM32 的 Flash，不代表单片机已经正常启动。

ST-Link 的 3.3V 供电引脚输出能力有限。开发板上电时，单片机、外设和电容可能需要较大的瞬时电流。如果 ST-Link 无法提供足够电流，3.3V 电压就会跌落，STM32 可能进入欠压复位或反复复位，表现为程序没有运行。

> 准确说法不是“启动时需要更大的电压”，而是“启动时需要较大的瞬时电流；供电能力不足使 3.3V 电压发生跌落”。

USB 的 `VBUS` 可以提供 5V，通常再通过开发板上的稳压电路转换成稳定的 3.3V。USB 的供电能力通常强于 ST-Link 的 3.3V 引脚，所以开发板可以正常启动。

```text
USB VBUS（5V）→ 板载稳压电路 → 3.3V → STM32 和板载外设
```

### 解决方法

- 使用 USB 给开发板供电；
- 使用 ST-Link 下载和调试程序；
- 保证 ST-Link 与开发板的 GND 相连；
- 开发板已有外部供电时，不随意同时连接 ST-Link 的 3.3V 输出，避免电源冲突。

## 8. LED 不亮时的排查顺序

1. 检查开发板供电是否稳定，电压和电流是否足够；
2. 检查 ST-Link 与开发板是否共地；
3. 检查程序是否真正烧录成功；
4. 根据原理图确认 LED 对应的 GPIO 引脚；
5. 判断 LED 是高电平点亮还是低电平点亮；
6. 检查 GPIO 时钟是否开启；
7. 检查 GPIO 是否配置为输出模式；
8. 检查 `MX_GPIO_Init()` 是否被调用；
9. 检查 BOOT、复位和系统时钟配置；
10. 最后检查主循环中的程序逻辑。
