# 03. KEY 控制 LED

## 1. 实验目标

- 学会根据原理图确定按键和 LED 对应的 GPIO 引脚；
- 使用 STM32CubeMX 配置 GPIO 输入和推挽输出；
- 使用 `HAL_GPIO_ReadPin()` 读取按键状态；
- 掌握按键的软件消抖和“按下一次只触发一次”的实现方法；
- 使用 KEY1、KEY2 分别控制红色和绿色 LED；
- 理解非 `void` 函数必须保证所有执行路径都有返回值；
- 掌握 ST-Link 无法下载程序时的基本排查方法。

---

## 2. 硬件信息

> 引脚和有效电平应以本开发板原理图以及本工程的 CubeMX 配置为准。

| 器件 | GPIO 端口 | GPIO 引脚 | 工作模式 | 有效电平 |
| --- | --- | --- | --- | --- |
| KEY1 | `GPIOA` | `PA0` | 输入 | 高电平按下 |
| KEY2 | `GPIOC` | `PC13` | 输入 | 高电平按下 |
| LED_G | `GPIOB` | `PB0` | 推挽输出 | 低电平点亮 |
| LED_R | `GPIOB` | `PB5` | 推挽输出 | 低电平点亮 |

对应的宏定义位于 `Core/Inc/main.h`：

```c
#define KEY2_Pin GPIO_PIN_13
#define KEY2_GPIO_Port GPIOC
#define KEY1_Pin GPIO_PIN_0
#define KEY1_GPIO_Port GPIOA
#define LED_G_Pin GPIO_PIN_0
#define LED_G_GPIO_Port GPIOB
#define LED_R_Pin GPIO_PIN_5
#define LED_R_GPIO_Port GPIOB
```

### LED 有效电平

本工程中的 LED 为低电平点亮：

```text
GPIO_PIN_RESET（低电平）→ LED 点亮
GPIO_PIN_SET（高电平）  → LED 熄灭
```

初始化时，程序先将 `PB0` 和 `PB5` 设置为高电平，因此两个 LED 默认熄灭。

---

## 3. 实验原理

程序首先初始化 GPIO，然后在 `while (1)` 中不断扫描 KEY1 和 KEY2：

```text
初始化 GPIO
    ↓
循环读取按键电平
    ↓
检测到按下后延时 20 ms 消抖
    ↓
再次确认按键仍然按下
    ↓
等待按键松开
    ↓
返回一次有效按键事件
    ↓
切换对应 LED 的状态
```

机械按键在按下和松开时，触点不会立即稳定，而会在短时间内多次接通、断开。如果不进行消抖，一次按键动作可能会被程序识别为多次按下。

---

## 4. STM32CubeMX 配置

### 4.1 配置按键引脚

1. 将 `PA0` 设置为 `GPIO_Input`，并设置 `User Label` 为 `KEY1`；
2. 将 `PC13` 设置为 `GPIO_Input`，并设置 `User Label` 为 `KEY2`；
3. 本工程将两路输入配置为 `GPIO_NOPULL`，按键的稳定电平由开发板外部电路提供。

### 4.2 配置 LED 引脚

1. 将 `PB0` 设置为 `GPIO_Output`，标签设置为 `LED_G`；
2. 将 `PB5` 设置为 `GPIO_Output`，标签设置为 `LED_R`；
3. 输出模式选择 `Output Push Pull`；
4. 上拉/下拉选择 `No pull-up and no pull-down`；
5. 输出速度选择 `Low`；
6. 初始输出电平设置为高电平，使 LED 上电后保持熄灭。

### 4.3 保留 ST-Link 调试接口

在 `System Core → SYS → Debug` 中选择 `Serial Wire`，为 ST-Link 保留 SWD 下载和调试接口。

SWD 主要使用以下两个引脚：

| 引脚 | 功能 |
| --- | --- |
| `PA13` | SWDIO，传输调试数据 |
| `PA14` | SWCLK，提供调试时钟 |

生成工程后，应确认 `main()` 中调用了：

```c
MX_GPIO_Init();
```

## 5. GPIO 初始化代码

本工程的初始化代码位于 `Core/Src/gpio.c`：

```c
void MX_GPIO_Init(void)
{
    GPIO_InitTypeDef GPIO_InitStruct = {0};

    /* 开启 GPIO 端口时钟 */
    __HAL_RCC_GPIOC_CLK_ENABLE();
    __HAL_RCC_GPIOA_CLK_ENABLE();
    __HAL_RCC_GPIOB_CLK_ENABLE();

    /* LED 默认输出高电平，即默认熄灭 */
    HAL_GPIO_WritePin(GPIOB, GPIO_PIN_0 | GPIO_PIN_5, GPIO_PIN_SET);

    /* KEY2：PC13 输入 */
    GPIO_InitStruct.Pin = GPIO_PIN_13;
    GPIO_InitStruct.Mode = GPIO_MODE_INPUT;
    GPIO_InitStruct.Pull = GPIO_NOPULL;
    HAL_GPIO_Init(GPIOC, &GPIO_InitStruct);

    /* KEY1：PA0 输入 */
    GPIO_InitStruct.Pin = GPIO_PIN_0;
    GPIO_InitStruct.Mode = GPIO_MODE_INPUT;
    GPIO_InitStruct.Pull = GPIO_NOPULL;
    HAL_GPIO_Init(GPIOA, &GPIO_InitStruct);

    /* LED_G：PB0；LED_R：PB5 */
    GPIO_InitStruct.Pin = GPIO_PIN_0 | GPIO_PIN_5;
    GPIO_InitStruct.Mode = GPIO_MODE_OUTPUT_PP;
    GPIO_InitStruct.Pull = GPIO_NOPULL;
    GPIO_InitStruct.Speed = GPIO_SPEED_FREQ_LOW;
    HAL_GPIO_Init(GPIOB, &GPIO_InitStruct);
}
```

其中：

- `__HAL_RCC_GPIOx_CLK_ENABLE()`：开启对应 GPIO 端口的时钟；
- `GPIO_MODE_INPUT`：将引脚配置为输入模式；
- `GPIO_MODE_OUTPUT_PP`：将引脚配置为推挽输出模式；
- `GPIO_NOPULL`：不使用芯片内部上拉或下拉电阻；
- `HAL_GPIO_Init()`：将结构体中的参数写入对应 GPIO 外设。

## 6. 按键扫描与软件消抖

### 6.1 原代码警告的原因

曾经使用过下面的写法：

```c
uint8_t KEY_Scan(GPIO_TypeDef *GPIOx, uint16_t GPIO_Pin)
{
    if (HAL_GPIO_ReadPin(GPIOx, GPIO_Pin) == GPIO_PIN_SET)
    {
        HAL_Delay(20);

        if (HAL_GPIO_ReadPin(GPIOx, GPIO_Pin) == GPIO_PIN_SET)
        {
            return 1;
        }

        return 0;
    }
}
```

如果第一次读取结果为 `GPIO_PIN_RESET`，外层 `if` 会被跳过，函数直接运行到末尾。由于该函数的返回类型为 `uint8_t`，所有执行路径都必须返回一个值，因此编译器会给出类似警告：

```text
control reaches end of non-void function
```

正确做法是在函数末尾统一补上 `return 0;`。

### 6.2 本工程使用的按键扫描函数

函数实现在 `Core/Src/gpio.c`，声明位于 `Core/Inc/gpio.h`：

```c
uint8_t KEY_Scan(GPIO_TypeDef *GPIOx, uint16_t GPIO_Pin)
{
    if (HAL_GPIO_ReadPin(GPIOx, GPIO_Pin) == GPIO_PIN_SET)
    {
        HAL_Delay(20);

        if (HAL_GPIO_ReadPin(GPIOx, GPIO_Pin) == GPIO_PIN_SET)
        {
            /* 等待松手，防止一次按压触发多次 */
            while (HAL_GPIO_ReadPin(GPIOx, GPIO_Pin) == GPIO_PIN_SET)
            {
            }

            HAL_Delay(20);
            return 1;
        }
    }

    return 0;
}
```

对应的函数声明为：

```c
uint8_t KEY_Scan(GPIO_TypeDef *GPIOx, uint16_t GPIO_Pin);
```

### 6.3 函数执行过程

1. 第一次读取为高电平，说明按键可能被按下；
2. 延时 20 ms，等待按下时的机械抖动结束；
3. 再次读取仍为高电平，确认这是一次有效按下；
4. 使用 `while` 等待按键松开，避免长按期间连续触发；
5. 松开后再次延时 20 ms，过滤松开时的抖动；
6. 返回 `1` 表示检测到一次完整按键动作，否则返回 `0`。

这种写法逻辑简单，适合当前入门实验。它的不足是等待松手期间 CPU 会一直阻塞，无法执行其他任务。后续可以使用状态机和系统节拍实现非阻塞消抖。

## 7. KEY 控制 LED

本工程在 `Core/Src/main.c` 的主循环中处理按键事件：

```c
while (1)
{
    /* KEY1：熄灭绿灯，翻转红灯状态 */
    if (KEY_Scan(KEY1_GPIO_Port, KEY1_Pin) == 1)
    {
        HAL_GPIO_WritePin(LED_G_GPIO_Port, LED_G_Pin, GPIO_PIN_SET);
        HAL_GPIO_TogglePin(LED_R_GPIO_Port, LED_R_Pin);
    }

    /* KEY2：熄灭红灯，翻转绿灯状态 */
    if (KEY_Scan(KEY2_GPIO_Port, KEY2_Pin) == 1)
    {
        HAL_GPIO_WritePin(LED_R_GPIO_Port, LED_R_Pin, GPIO_PIN_SET);
        HAL_GPIO_TogglePin(LED_G_GPIO_Port, LED_G_Pin);
    }
}
```

### 实际控制逻辑

| 按键 | 固定执行 | 翻转执行 | 实际效果 |
| --- | --- | --- | --- |
| KEY1 | 将 LED_G 设置为高电平 | 翻转 LED_R | 绿灯熄灭，红灯亮灭状态切换 |
| KEY2 | 将 LED_R 设置为高电平 | 翻转 LED_G | 红灯熄灭，绿灯亮灭状态切换 |

`HAL_GPIO_TogglePin()` 会将当前电平翻转：

```text
高电平 → 低电平：LED 由灭变亮
低电平 → 高电平：LED 由亮变灭
```

因此，每完整按下并松开一次按键，对应 LED 只切换一次状态。同时，程序会先熄灭另一只 LED，所以红灯和绿灯不会同时点亮。

---

## 8. 实验现象

- 程序能够正常编译并通过 ST-Link 烧录；
- 上电后红色和绿色 LED 默认熄灭；
- 每按下并松开一次 KEY1，红色 LED 的亮灭状态切换一次，同时绿色 LED 熄灭；
- 每按下并松开一次 KEY2，绿色 LED 的亮灭状态切换一次，同时红色 LED 熄灭；
- 按住按键不松开时，不会连续反复切换 LED。

## 9. 本次遇到的问题

### 9.1 `KEY_Scan()` 出现返回值警告

#### 问题现象

编译器提示：

```text
control reaches end of non-void function
```

#### 原因分析

`KEY_Scan()` 的返回类型为 `uint8_t`，但原代码没有保证所有执行路径都有返回值。当按键未按下时，程序可能直接运行到函数末尾。

#### 解决方法

在函数末尾添加：

```c
return 0;
```

### 9.2 一次按键触发多次

#### 原因分析

- 机械触点在按下和松开时存在抖动；
- 主循环执行速度很快；
- 如果只判断当前电平，按住期间会被重复识别为多次按下。

#### 解决方法

- 按下后延时 20 ms，再次读取确认；
- 确认按下后等待松手；
- 松手后再次延时 20 ms；
- 后续复杂工程中使用非阻塞状态机消抖。

### 9.3 ST-Link 连接正常但无法烧录

#### 问题现象

ST-Link 可以被电脑识别，但 Keil 无法连接目标芯片或提示：

```text
No target connected
Flash Download failed
```

#### 原因分析

CubeMX 中没有将 `System Core → SYS → Debug` 设置为 `Serial Wire`，导致程序重新配置了 `PA13` 和 `PA14`，SWD 下载与调试接口无法正常使用。

#### 解决方法

1. 在 CubeMX 中选择 `System Core → SYS`；
2. 将 `Debug` 设置为 `Serial Wire`；
3. 重新生成、编译并烧录工程；
4. 检查 ST-Link 与开发板是否共地、供电是否稳定；
5. 如果旧程序已经占用了 SWD 引脚，可尝试按住复位键连接，在开始下载时松开复位键。

```text
未保留 Serial Wire
        ↓
PA13、PA14 被程序占用
        ↓
ST-Link 能被电脑识别
        ↓
但无法通过 SWD 连接 STM32
```

## 10. 常见问题排查顺序

1. 检查开发板供电是否稳定，ST-Link 是否与开发板共地；
2. 检查 CubeMX 是否启用了 `Serial Wire`；
3. 根据原理图确认按键和 LED 的端口、引脚及有效电平；
4. 检查 GPIOA、GPIOB、GPIOC 的时钟是否开启；
5. 检查按键是否配置为输入，LED 是否配置为推挽输出；
6. 检查 `MX_GPIO_Init()` 是否在主循环之前调用；
7. 使用 `HAL_GPIO_ReadPin()` 或 Keil Watch 观察按键电平是否变化；
8. 检查 `KEY_Scan()` 是否在所有执行路径上都有返回值；
9. 检查 LED 是否为低电平点亮，避免把控制电平写反；
10. 检查等待松手的 `while` 是否因为按键电平异常而无法退出。

## 11. 实验总结

本实验掌握了：

- 根据原理图和 CubeMX 工程确认按键、LED 的 GPIO 引脚；
- 使用 GPIO 输入读取按键状态；
- 使用 GPIO 推挽输出控制低电平点亮的 LED；
- 使用两次采样和延时实现基础软件消抖；
- 使用等待松手实现“一次按压只触发一次”；
- 理解非 `void` 函数必须保证所有路径都有返回值；
- 使用 KEY1 和 KEY2 分别切换红灯和绿灯；
- 在 CubeMX 中保留 Serial Wire，避免 SWD 下载接口失效。

> 核心过程：查看原理图 → 配置输入和输出 → 读取按键 → 软件消抖 → 等待松手 → 切换 LED → 排查下载与运行问题。
